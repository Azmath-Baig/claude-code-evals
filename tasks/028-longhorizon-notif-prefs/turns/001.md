Build a notification preferences feature on top of the existing `notifications.py`.

- Existing API clients must remain backward compatible: `get_user_notification_settings(user_id)` and its return shape (`{"email": bool, "in_app": bool}`) must keep working exactly as today.
- Users can configure two channels, `email` and `in_app`. Add `set_user_preference(user_id, channel, enabled)` and `get_user_preference(user_id, channel)`.
- Preferences must persist for the life of the process.
- Default behavior for existing users must not change: a user who has never set a preference for a channel should see the same default `get_user_notification_settings` gives today.
- Admins can manage the org-wide default for a channel but can never override a preference a specific user has explicitly set. Add `ADMIN_IDS = {"admin1"}` and `set_admin_default(admin_user_id, channel, enabled)` — only an id in `ADMIN_IDS` may call it.
- Add tests.
- Don't modify `billing.py` or anything unrelated to this feature.
